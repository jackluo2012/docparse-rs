# devlog · `-f meta` 文档元数据（Phase 28 · 计划 P2）

> 计划：[plans/2026-09-06-cli-interface-ergonomics.md](../plans/2026-09-06-cli-interface-ergonomics.md) §3.2。2026-09-06。

## 做了什么

- **IR**：`Document.metadata: Option<Metadata>` + 9 字段 `Metadata`（全 Option）。serde `default` + `skip_serializing_if = "Option::is_none"` 双保险：无元数据文档的 `-f json` 字节与 0.8.0 完全一致（csv 冒烟验证 `grep -c metadata` = 0）。`SCHEMA_VERSION` → 0.9.0，document.json golden 重生成 + 新 meta.json。
- **五个后端填充**：
  - **pdf**（新 `metadata.rs`）：trailer `/Info` → `get_object(as_reference())` 解引用 → 六字符串字段 + 两日期。日期 `D:YYYYMMDDHHmmSS±HH'mm'` → ISO 8601 UTC（days_from_civil/civil_from_days 一对纯函数，offset 参与换算、可跨日界，表驱动单测含垃圾输入→None）。字符串解码 UTF-16BE(BOM)/逐字节，与 outlines.rs 书签标题同约定。
  - **docx/pptx/xlsx**：共用 `core::meta::ooxml_metadata_from_zip(buf)` 读 `docProps/core.xml`（quick-xml 事件流，剥命名空间前缀取 local name；`dc:creator`→author，`dcterms:*` 本就是 ISO 直接透传）。core 增 quick-xml + zip（workspace 内部依赖，零新增供应链面）——三后端共用一份解析，DRY。
  - **html**：DOM 单次遍历取 `<title>` 文本、`meta[name=author|keywords]`、`html lang`。`Some(空 Metadata)` 表示"此格式有元数据源但页面没填"——与 `None`（格式根本无源）区分。
  - 其余后端 `metadata: None`（诚实缺省）；EML 元数据（From/To/Subject/Date）是显然后续项。
- **`-f meta`**：`MetaReport{source, parser, page_count, metadata}` 投影，CLI/REST 同源；MCP 侧 parse_document json 自动携带 metadata 字段（序列化即含）。

## 踩坑（两个都是 fixture 的错，不是代码的）

1. **lopdf `From<&str>` 产出 Name 对象**：`dictionary!{"Title" => "X"}` 经保存/重载后 `as_str()` 报 `expected: "String", found: "Name"`。用独立 probe 程序 dump 对象确认。Info 字符串必须 `Object::string_literal`。已在 fixture 注释点名。
2. **真实 PDF 的 `/Info` 是间接引用**：第一版 fixture 把字典内联进 trailer，`as_reference()` 解不出来。改为 `add_object` + trailer 存引用（真实文件形态），reader 代码未动。

另：`enhance.rs::apply` 的 Document 重组需显式携带 metadata（增强不丢元数据）；`Document` 加字段波及 ~20 处字面量，编译器逐一指出后机械补 `metadata: None`。
