# devlog · stdin `-` 与 URL 直输（Phase 30 · 计划 P4+P5）

> 计划：[plans/2026-09-06-cli-interface-ergonomics.md](../plans/2026-09-06-cli-interface-ergonomics.md) §3.4/§3.5。2026-09-06。

## 做了什么

两形态共用一个**输入物化层**（新 [cli/input_source.rs](../../crates/docparse-cli/src/input_source.rs)）：

- **物化模型**：stdin/URL 都落成带正确扩展名的临时文件 → `cli.inputs[0]` 换成该路径 → 既有单文件管线（backend 分发、`--pages`、增强、渲染、`-o`）零感知。`TempInput` Drop 即删（best-effort）。`main()` 里 `cli` 改 `mut` 以原地替换输入。
- **格式判定链**（显式优先，拒绝猜测）：`--input-format <FMT>`（12 解析器名的 ValueEnum，`from_name` 直接迭代 clap 的 `value_variants()` 单一来源）→ stdin `%PDF-` 5 字节 magic（唯一值得做的嗅探：精确字节、覆盖 `curl | docparse -` 主流场景）→ URL path 后缀（大小写不敏感）→ Content-Type（`application/pdf`/`text/html`/`text/markdown`/`text/csv`/… 6 种）→ 报错列出全部合法格式并点名 `--input-format`。`text/plain`→txt、`application/json`→json 故意不进映射表（没有 txt/json 解析器，宁可报错不猜）。
- **URL**：workspace 已有 ureq（cli 加 `ureq.workspace = true`，零新供应链面）；30s 超时、≤5 重定向；错误带 URL 与状态。**边界**：仅本地 CLI、仅单输入（与多输入/`--out-dir` 组合明确报错）；REST/MCP 不做 URL 拉取——服务端按用户 URL 发请求是真 SSRF 面（计划 §2 评审定死）。下载阶段 stderr spinner（非 TTY 静默）。
- **拒收组合**：`-`/URL 与 folder/多输入组合 → "must be the only input"；与 `--out-dir` 组合 → 明确报错。

## 验证

- 单测 5：显式格式压倒一切 / URL 后缀与 Content-Type 回退（含 charset 参数剥离、`.MD` 大写、尾斜杠剥）/ 不可判定报错点名 flag 且列出 `pdf|docx` / magic 判定 / URL path 提取（query/fragment/尾斜杠）。
- 冒烟：`cat demo.pdf | docparse - --pages 3 -f text`（magic + 页范围组合）✓；`printf '# …' | docparse - --input-format md -f text` ✓；无格式报错文案 ✓；本地 `python3 -m http.server` 下载 `--pages 2` ✓；多输入拒绝 ✓；`ls /tmp/docparse-input-*` 为空（清理）✓。
- 首次 URL 冒烟空输出是 http.server 启动竞态（sleep 不够），非代码问题；重跑正常。
- workspace 372 全绿、clippy 零新增、fmt 过。

## 遗留

- URL 断点续传/认证头（`--header`）：未做（公开文档场景优先，真需求出现再加）。
- stdin 大文档全量入内存：与既有解析内存模型一致（PDF 后端本就整读），计划 §9 明确不做流式（YAGNI）。

~1.5h（含 http.server 竞态的一次误判排查）。
